07 / Data Model · 数据模型

5 张表 · 以 apis 为核心

SQLAlchemy 2.0 声明式映射，所有子表通过 api_id 外键关联 apis，统一 CASCADE 级联删除。统计指标由 CheckLog 实时计算，无需预聚合表。

01
apis · 接口配置
含 body_type (json/data) 决定请求体发送方式，1→N 关联日志/告警。
02
check_logs · 巡检日志
记录每次巡检 status / http_status / response_time_ms / error_message。
03
alerts + api_authorizations
告警状态机 (pending/resolved) + 接口-用户多对多授权关联表。
08 / Business Flow · 业务流程

定时巡检 · 告警联动闭环

APScheduler 每 60 秒触发全量巡检，串联巡检引擎 → 告警检测 → 自动恢复 → 升级通知，全程写审计日志。

60s 巡检周期
3次 失败重试
20 并发上限
2h 升级阈值
CHECK & ALERT FLOW · 巡检告警链路
ALERT RULES · 三类告警
response_timeout
响应时间 > api.timeout 阈值
status_code_error
status=failure 且有 http_status
consecutive_failure
最近 3 条日志全部 failure
聚合 · 升级 · 恢复
同类型 pending 不重复 · >2h 升级 · 成功自动 resolve
09 / RBAC · 角色权限矩阵

三级角色 · 最小权限原则

admin 全权管理，operator 限定授权接口的运维操作，viewer 仅查看；接口授权表精细化控制 operator 可见范围。

操作 / Operation Admin Operator Viewer
仪表盘 / 日志 / 告警 / 报表查看 ✓ 全部 ✓ 仅授权接口 ✓
接口 CRUD · 批量操作 · 授权 ✓ ✗ ✗
手动巡检 ✓ ✓ ✗
解决告警 ✓ ✓ ✗
报表导出 · 审计日志下载 ✓ ✗ ✗
用户管理 · 用户授权接口 ✓ ✗ ✗
