# 企业接口巡检与稳定性监控系统

## 需求说明书

版本：v1.0 / 最后更新：2026年7月 / 文档状态：已定稿

---

## 1. 项目概述

### 1.1 项目背景

在微服务架构盛行的今天，企业内部通常维护着数十甚至上百个 API 接口。这些接口的可用性和响应速度直接影响到业务系统的稳定性。目前缺乏统一的接口监控手段，导致以下问题：

- 接口故障发现滞后，影响用户体验
- 无法量化接口的稳定性指标
- 缺乏历史数据支撑性能优化决策

### 1.2 项目目标

构建一个轻量级的企业接口巡检与稳定性监控系统，实现对核心 API 接口的自动化监控、异常告警和稳定性分析。

## 2. 功能需求（按模块）

### 模块A：接口管理模块

管理被监控接口的配置信息，包括增删改查、分组、标签。

| 功能模块 | 需求描述 | 优先级 | 实现状态 |
|:---|:---|:---:|:---:|
| 新增接口 | 支持添加需要监控的 API 接口，配置 URL、请求方法、超时时间、期望状态码 | P0 | ✅ |
| 编辑接口 | 支持修改已配置接口的参数 | P0 | ✅ |
| 删除接口 | 支持删除不再监控的接口 | P0 | ✅ |
| 启用/停用 | 支持单独启用或停用某个接口的巡检 | P0 | ✅ |
| 接口列表 | 展示所有已配置接口及其当前状态 | P0 | ✅ |
| 分组管理 | 支持按业务线/系统对接口进行分组 | P1 | ✅ 字段支持 |
| 标签管理 | 支持为接口添加自定义标签便于筛选 | P2 | ✅ 字段支持 |

```json
// 接口配置字段示例
{"name":"用户服务-登录接口","url":"https://api.example.com/user/login","method":"POST","headers":{"Content-Type":"application/json"},"body":{"username":"test","password":"test123"},"timeout":5000,"expected_status":200,"expected_response_time":1000,"check_interval":300,"enabled":true,"group_name":"用户服务","tags":["核心接口","POST"]}
```

### 模块B：巡检调度模块

定时调用目标接口，记录调用结果，是巡检系统的核心执行引擎。

| 功能模块 | 需求描述 | 优先级 | 实现状态 |
|:---|:---|:---:|:---:|
| 定时巡检 | 按配置的间隔（如 5 分钟）自动执行接口调用 | P0 | ✅ |
| 立即执行 | 支持手动触发一次巡检 | P0 | ✅ |
| 并发控制 | 支持配置最大并发数（全局配置 `MAX_CONCURRENT_CHECKS`），避免对被测系统造成压力 | P1 | ✅ asyncio.Semaphore |
| 重试机制 | 调用失败时自动重试（最多 3 次），重试间隔递增（2s/4s/6s） | P1 | ✅ |
| 超时处理 | 请求超过配置时间自动中断并记录 | P0 | ✅ |

```json
// 巡检日志字段示例
{"check_id":"ck_20260128_001","api_id":1,"status":"success","http_status":200,"response_time_ms":152,"response_size":1024,"response_summary":"{\"code\":200,\"message\":\"success\"}","error_message":null,"check_time":"2026-01-28T10:30:00Z"}
```

### 模块C：告警管理模块

基于巡检结果判断异常状态，通过多渠道发送告警通知，并在前端触发声音提醒。

| 功能模块 | 需求描述 | 优先级 | 实现状态 |
|:---|:---|:---:|:---:|
| 连续失败告警 | 连续 N 次（如 3 次）失败后触发告警 | P0 | ✅ |
| 响应时间超阈值 | 响应时间超过配置阈值时告警 | P0 | ✅ |
| 恢复通知 | 接口从故障状态恢复时自动解决告警并发送通知 | P1 | ✅ |
| 告警方式 | 通知渠道基类 `NotificationChannel`，当前写入审计日志；可扩展对接钉钉、企业微信、邮件、短信 | P0 | ✅ 可扩展架构 |
| 告警聚合 | 相同告警在未解决前不重复创建 | P1 | ✅ |
| 告警升级 | 告警持续超过 `ALERT_ESCALATION_HOURS`（默认2小时）未解决时升级通知 | P2 | ✅ |

**前端声音提醒（新增）：**
| 功能模块 | 需求描述 | 优先级 |
|:---|:---|:---|
| 新告警声音提示 | 新告警产生时前端浏览器播放提示音（通过 WebSocket 或轮询检测） | P0 |
| 声音开关 | 用户在页面右上角设置中可开启/关闭告警声音 | P0 |
| 页面标题闪烁 | 页面失去焦点时，新告警触发页面标题闪烁"⚠ 有新告警" | P1 |

### 模块F：操作审计模块

记录用户关键操作，提供安全追溯能力。操作日志写入**文件系统**（`logs/operation.log`），采用 Python logging 按日轮转，不占用数据库空间。

| 功能模块 | 需求描述 | 优先级 | 实现状态 |
|:---|:---|:---:|:---:|
| 操作自动记录 | 用户执行增删改操作时自动写入日志文件 | P1 | ✅ 覆盖接口CRUD/用户CRUD/手动巡检/解决告警 |
| 操作详情 | 日志记录：操作人、IP、操作类型、操作对象、操作时间 | P1 | ✅ |
| 日志轮转 | 按日轮转，保留最近 90 天日志，自动压缩归档 | P1 | ✅ |
| 审计查询 | admin 可通过 `/api/logs/download?date=YYYY-MM-DD` 下载指定日期日志 | P1 | ✅ |

**日志格式（每行一条 JSON）：**
```
{"timestamp":"2026-01-28T10:30:00Z","user":"admin","ip":"192.168.1.100",
 "action":"resolve","target_type":"alert","target_id":5,"detail":"解决告警-响应超时"}
```

**记录覆盖的操作类型：**

| 操作 | action 值 | 触发场景 |
|:---|:---|:---|
| 新增接口 | `create` | 用户通过 API 新增接口配置 |
| 编辑接口 | `update` | 用户修改接口配置 |
| 删除接口 | `delete` | 用户删除接口 |
| 解决告警 | `resolve` | 用户确认/解决告警 |
| 手动巡检 | `check` | 用户手动触发接口巡检 |
| 新增用户 | `create` | admin 创建新用户 |
| 编辑用户 | `update` | admin 修改用户信息 |
| 删除用户 | `delete` | admin 删除用户 |

## 3. 前端界面功能展示（按页面分级）

### 3.0 登录页（Login）

**路由：** `/login`

**功能定位：** 用户身份认证入口，支持多用户登录，根据角色控制功能访问权限。

| 区域 | 组件类型 | 功能说明 |
|:---|:---|:---|
| 登录表单 | Form | 用户名输入框、密码输入框、登录按钮、表单校验（非空、密码长度） |
| 登录状态 | Message / Alert | 登录失败时显示错误提示（"用户名或密码错误"），登录成功跳转到仪表盘 |
| 记住我 | Checkbox | 可选记住登录状态（localStorage 存储 Token） |

**角色权限：**

| 角色 | 权限范围 |
|:---|:---|
| admin（管理员） | 全部功能：接口管理 CRUD、手动巡检、告警处理、统计报表查看、用户管理 |
| operator（运维） | 接口查看、手动巡检、告警处理、统计报表查看（不可增删改接口） |
| viewer（只读） | 仪表盘、接口列表查看、日志查看、告警查看（不可执行巡检和修改配置） |

**交互要求：**
- 未登录状态下访问任何页面自动跳转到 `/login`
- 登录成功后跳转到原目标页面（如访问 `/apis` 未登录 → 登录成功后自动跳回 `/apis`）
- 退出登录清除 Token，跳回登录页
- 所有 API 请求自动附带 Token（请求头 `Authorization: Bearer <token>`），401 响应时自动跳转登录页
- 无注册功能（由管理员在后台添加用户）

### 4.3 SQLAlchemy ORM 完整模型代码

以下为使用 SQLAlchemy 2.0+ 声明式映射定义的全部 5 张表的完整代码。

```python
import datetime
from sqlalchemy import BigInteger, String, Text, Integer, SmallInteger, \
    DateTime, Date, ForeignKey, Index
from sqlalchemy.orm import DeclarativeBase, relationship, Mapped, mapped_column
from sqlalchemy.sql import func as sqlfunc


class Base(DeclarativeBase):
    pass


class Api(Base):
    """接口配置表"""
    __tablename__ = "apis"

    __table_args__ = (
        Index("idx_api_enabled", "enabled"),
        Index("idx_api_group", "group_name"),
        {"comment": "接口配置表"},
    )

    id: Mapped[int] = mapped_column(
        BigInteger, primary_key=True, autoincrement=True, comment="接口ID"
    )
    name: Mapped[str] = mapped_column(
        String(200), nullable=False, comment="接口名称"
    )
    url: Mapped[str] = mapped_column(
        String(500), nullable=False, comment="接口URL"
    )
    method: Mapped[str] = mapped_column(
        String(10), nullable=False, comment="HTTP请求方法"
    )
    headers: Mapped[str | None] = mapped_column(
        Text, nullable=True, comment="请求头(JSON格式)"
    )
    body: Mapped[str | None] = mapped_column(
        Text, nullable=True, comment="请求体(JSON格式)"
    )
    timeout: Mapped[int] = mapped_column(
        Integer, nullable=False, default=5000, comment="超时时间(毫秒)"
    )
    expected_status: Mapped[int] = mapped_column(
        Integer, nullable=False, default=200, comment="期望状态码"
    )
    expected_response_time: Mapped[int] = mapped_column(
        Integer, nullable=False, default=1000, comment="期望响应时间(毫秒)"
    )
    check_interval: Mapped[int] = mapped_column(
        Integer, nullable=False, default=300, comment="巡检间隔(秒)"
    )
    enabled: Mapped[bool] = mapped_column(
        SmallInteger, nullable=False, default=1, comment="是否启用: 1启用 0禁用"
    )
    group_name: Mapped[str | None] = mapped_column(
        String(100), nullable=True, comment="业务分组"
    )
    tags: Mapped[str | None] = mapped_column(
        Text, nullable=True, comment="标签(JSON数组)"
    )
    created_at: Mapped[datetime.datetime] = mapped_column(
        DateTime, nullable=False, server_default=sqlfunc.now(), comment="创建时间"
    )
    updated_at: Mapped[datetime.datetime] = mapped_column(
        DateTime, nullable=False,
        server_default=sqlfunc.now(), onupdate=sqlfunc.now(),
        comment="更新时间"
    )

    # 反向关系
    check_logs: Mapped[list["CheckLog"]] = relationship(
        back_populates="api", cascade="all, delete-orphan"
    )
    alerts: Mapped[list["Alert"]] = relationship(
        back_populates="api", cascade="all, delete-orphan"
    )
    daily_stats: Mapped[list["ApiStatsDaily"]] = relationship(
        back_populates="api", cascade="all, delete-orphan"
    )


class CheckLog(Base):

    __table_args__ = (
        Index("idx_cl_api_id", "api_id"),
        Index("idx_cl_status", "status"),
        Index("idx_cl_check_time", "check_time"),
        {"comment": "巡检日志表"},
    )

    id: Mapped[int] = mapped_column(
        BigInteger, primary_key=True, autoincrement=True, comment="日志ID"
    )
    api_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("apis.id", ondelete="CASCADE"),
        nullable=False, comment="关联接口ID"
    )
    status: Mapped[str] = mapped_column(
        String(20), nullable=False, comment="状态: success/failure"
    )
    http_status: Mapped[int | None] = mapped_column(
        Integer, nullable=True, comment="HTTP响应状态码"
    )
    response_time_ms: Mapped[int | None] = mapped_column(
        Integer, nullable=True, comment="响应时间(毫秒)"
    )
    response_size: Mapped[int | None] = mapped_column(
        Integer, nullable=True, comment="响应体大小(字节)"
    )
    response_summary: Mapped[str | None] = mapped_column(
        Text, nullable=True, comment="响应内容摘要"
    )
    error_message: Mapped[str | None] = mapped_column(
```

### 4.4 外键关联汇总

| 子表 | 外键字段 | 引用主表 | 引用字段 | 级联删除 |
|:---|:---|:---|:---|:---:|
| `check_logs` | `api_id` | `apis` | `id` | CASCADE |
| `alerts` | `api_id` | `apis` | `id` | CASCADE |
| `api_stats_daily` | `api_id` | `apis` | `id` | CASCADE |

### 4.5 字段来源映射

| 表 | 字段 | 写入来源 | 写入时机 |
|:---|:---|:---|:---|
| apis | 全部字段 | 用户通过API提交 | 创建/编辑接口时 |
| apis | created_at / updated_at | 数据库自动 | INSERT/UPDATE时 |
| check_logs | api_id | 巡检引擎 | 巡检执行时，从api上下文获取 |
| check_logs | status / http_status / response_time_ms | 巡检引擎 | HTTP响应到达后 |
| check_logs | error_message | 巡检引擎 | 仅在 status=failure 时写入 |
| check_logs | check_time | 巡检引擎 | 巡检发起时记录 |
| alerts | api_id | 告警引擎 | 触发告警时 |
| alerts | alert_type / message | 告警引擎 | 根据告警规则判定和生成 |
| alerts | status | 告警引擎 / 用户确认 | 初始 pending，用户确认后 resolved |
| alerts | resolved_at | 告警引擎 / 用户确认 | 告警解决时写入 |
| api_stats_daily | 全部字段 | 日终批处理 / 定时任务 | 每日统计汇总后写入 |
| users | 全部字段 | admin 通过API创建 | 管理员添加用户时写入 |
| users | password_hash | 用户注册 / 管理员设置 | 注册或修改密码时写入 |

## 7. 告警规则

### 7.1 内置告警规则

| 规则名称 | 触发条件 | 默认阈值 | 后端实现 |
|:---|:---|:---:|:---:|
| 连续失败 | 连续失败次数 >= N | N=3 | ✅ |
| 响应超时 | 响应时间 > 超时时间配置 | 5000ms | ✅ |
| 响应慢 | 响应时间 > 期望响应时间 × 1.5 | 1500ms | ✅（触发 warning 状态） |
| 状态码异常 | HTTP状态码 != 期望状态码 | 200 | ✅ |
| 可用性下降 | 5分钟成功率 < 80% | 80% | ✅（通过巡检结果判定） |
| **告警升级** | 告警持续未解决 > `ALERT_ESCALATION_HOURS` | 2小时 | ✅ |
| **恢复通知** | 接口从 failure 恢复为 success | 自动 | ✅ |

### 7.2 告警级别

| 级别 | 说明 |
|:---|:---:|
| 严重 (ERROR) | 接口不可用，需立即处理 |
| 警告 (WARNING) | 性能下降或有异常趋势 |
| 恢复 (RESOLVED) | 接口已恢复正常 |

### 7.3 通知渠道（后端实现）

| 渠道 | 目标 | 触发时机 | 实现状态 |
|:---|:---|:---|:---:|
| `NotificationChannel.send()` | 操作审计日志 | 新告警/恢复/升级时 | ✅ 基类实现 |
| 钉钉机器人 | 钉钉群 | 告警产生时 | 🔧 可扩展（需子类实现 Webhook） |
| 企业微信机器人 | 企业微信群 | 告警产生时 | 🔧 可扩展 |
| 邮件通知 | 运维人员邮箱 | 告警产生时 | 🔧 可扩展 |

### 7.4 前端告警声音与角标联动

| 条件 | 行为 |
|:---|:---|
| 新告警产生（后端写入 alerts 表，status=pending） | WebSocket 推送 → 前端播放提示音 → 🔔 角标 +1 |
| 用户已开启"声音提醒"开关 | 播放默认提示音（短促的"叮"声，约 0.5s） |
| 用户已关闭"声音提醒"开关 | 不播放声音，仅更新 🔔 角标 |
| 页面处于后台/失焦状态 | 🔔 角标 +1 + 页面标题闪烁"⚠ 有新告警" |
| 用户切换到告警管理页并解决告警 | 🔔 角标 -1，下拉列表移除该告警 |

## 8. 非功能需求

### 8.1 性能要求

| 指标 | 要求 |
|:---|:---|
| 巡检并发数 | 支持 50+ 接口同时巡检 |
| 单次巡检耗时 | < 30 秒（50 个接口） |
| API 响应时间 | < 200ms (P95) |
| 数据保留 | 日志保留 30 天，统计表永久保留 |

### 8.2 可用性要求

| 指标 | 要求 |
|:---|:---|
| 系统可用性 | 99.5%（每年宕机时间 < 43.8 小时） |
| 巡检准确性 | 误报率 < 1% |
| 数据持久化 | 支持数据库备份与恢复 |

### 8.3 扩展性

- 支持水平扩展（多实例部署）
- 支持添加自定义检查脚本（如：检查响应内容是否包含关键词）
- 支持对接 Prometheus 等监控系统

### 8.4 安全性

- **用户认证**：支持多用户登录，JWT Token 鉴权，Token 有效期 24 小时
- **角色权限**：admin / operator / viewer 三级权限，API 端点按角色控制访问
- **密码安全**：密码使用 bcrypt 哈希存储，不存储明文密码
- **操作审计**：所有增删改操作写入 `logs/operation.log`（按日轮转 JSON 文件），支持按用户/对象追溯
- **接口配置加密**：敏感信息（如密码/Token）需加密存储
- 支持 HTTPS

### 8.5 前端非功能需求（新增）

| 指标 | 要求 |
|:---|:---|
| 响应式布局 | 支持 PC（≥1200px）和平板/手机（<768px）两种布局；PC 侧边栏常驻，移动端底部 TabBar |
| 首屏加载 | 首屏加载时间 < 3s（含 API 数据请求） |
| 数据刷新 | 仪表盘数据 30 秒自动轮询；🔔 告警计数实时更新（WebSocket 优先，降级为 30s 轮询） |
| 声音提醒 | 新告警产生时 Web Audio API 播放提示音，用户可开关，默认开启 |
| 离线告警 | 页面失焦时新告警触发页面标题闪烁"⚠ 有新告警"，用户切回页面后标题恢复 |
| 浏览器兼容 | 支持 Chrome / Firefox / Edge 最新两个大版本 |
| 可用性 | 前端静态资源部署 CDN，保证 99.9% 可用性 |
